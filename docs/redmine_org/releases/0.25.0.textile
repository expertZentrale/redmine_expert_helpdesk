h3. Fixed

* *A slow or failing mail service can no longer take Redmine down.* The cron fetch (@helpdesk/fetch_all@) runs inside a web request and holds an application server thread while it waits for the mail service. In an Exchange Online outage every Graph call hung for 30 seconds, one run over several mailboxes took minutes, and a reverse proxy that retried the request filled every thread until nobody could log in. Now:
** only one @fetch_all@ runs at a time; a second call answers at once with @"skipped": true@
** a run starts no mailbox and no message after 150 seconds; the rest is fetched next time
** once a mail service times out or answers with a server error, the remaining mailboxes on that service wait for the next run instead of each waiting for its own timeout
** a message that failed because the service did, before Redmine processed it, stays unread in the mailbox instead of going to the error folder
** Microsoft Graph calls give up after 20 seconds instead of 60 (downloading and sending a mail keep 60)
** the phishing feed sync runs as a background job when a feed is due, instead of keeping the request busy for minutes

h3. Added

* *The automation keys can be sent as a header.* @fetch_all@, @sla_check@ and @maintenance@ accept @Authorization: Bearer <key>@. @?key=@ still works, but a query string ends up in proxy and access logs.

h3. Upgrade notes

No new migrations, no new settings. Replace the plugin directory and restart.

The one-at-a-time lock lives in Redmine's cache. The default file cache covers all processes on one server. With several application servers, configure a shared cache (Redis or Memcached), or two servers can fetch the same mailbox at once.

Call @fetch_all@ directly rather than through a proxy that retries timed-out requests, and keep the client timeout below the cron interval, e.g. @curl --max-time 240 -H "Authorization: Bearer KEY" https://redmine.example.com/helpdesk/fetch_all@.
