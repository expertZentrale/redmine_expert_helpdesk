h3. Added

* *The AI can now draft the answer to the customer, not just the summary for the agent.* Every AI feature so far pointed inward: the summary condenses the customer's mail for the agent, the completeness check judges it, and the knowledge base files a repair note written for a colleague. The one customer-facing feature, answer templates, is static and knows nothing about the ticket in front of you — so agents kept writing every real answer by hand, even when the identical case had been solved and filed last month. A third button, *AI answer*, now sits next to *Quote* and *Templates* in the toolbar of the note field. It drafts a reply addressed to the customer for this ticket — what they should do, in order — grounded in that project's own knowledge base, and appends it to the note field, which is also the body of the outgoing mail. Four variants: a standard answer, step-by-step instructions, a short version, and one that asks for the missing details. Nothing is ever sent automatically: the draft is inserted for the agent to read, edit and send through the normal reply form.
* *Without a matching knowledge base entry, no draft is produced.* An ungrounded reply is exactly the artefact that invents a repair date, so the three variants that propose a fix refuse and name the answer templates as the alternative. *Ask for missing details* is the exception — it proposes nothing, needs no grounding, and therefore works from the first day against an empty knowledge base. How similar a match has to be is configurable centrally and per project (@ai_answer_min_score@, default 0.65), deliberately separate from the knowledge base's own minimum score: tightening what reaches customers must not also suppress the proposals agents see inside a summary. When a draft is refused, the message names the near miss — "best match 86%, 95% required" — so the threshold can be calibrated from real cases instead of guessed.
* *Internal information stays internal.* Unlike the knowledge base extractor, whose output never leaves the project, the drafter is never given private notes or attachments, and the knowledge base cases it works from are passed *without their ticket numbers* — a foreign ticket number in a customer mail discloses the existence, and by inference the content, of another customer's ticket. The prompt additionally forbids prices, dates, deadlines, supplier and colleague names, internal tooling, and any promise of repair, replacement, goodwill or warranty that is not already in the ticket. Which tickets a draft was built on is shown to the agent in the toolbar status line, never written into the mail.
* *No double salutation, and nothing inserted silently.* The mailbox's reply header and footer are rendered and handed to the model, which is told they will be placed around its text, so the customer does not receive two greetings or two signatures. Inserted text is marked by a warning bar above the note field, and sending or saving a draft that has not been edited asks for confirmation first. Any note that came from a draft is kept out of knowledge base ingestion, so the model never re-reads its own prose as a solution.

h3. Fixed

* *The plugin's secrets no longer appear in the request log.* Every secret the plugin stores was written to the Rails parameter log in clear text whenever an administrator saved the settings form: the AI provider key, the embedding key, the Qdrant key, the keys securing the mail-fetch and SLA endpoints — and, on Redmine 5.1 and 6.0, the Azure Client Secret as well, which is only covered by the application's own filter list on 6.1 and 7.0. On a container installation that log goes wherever standard output goes, with a retention that has nothing to do with the ticket data. The plugin now registers its own filters instead of inheriting any, so the values appear as @[FILTERED]@ on every supported version, while ordinary settings such as the model name stay readable.

h3. Upgrade notes

Five migrations run on upgrade (052–056). They add the per-project settings for the answer drafts, record which agent triggered an AI call, and mark replies and notes that came from a draft. Nothing changes behaviour on upgrade: the feature is off centrally *and* off in every project, so no ticket, mailbox or existing AI setting is affected until it is switched on twice — once under *Administration → Plugins → Redmine expert Helpdesk*, then per project under *Settings → expert Helpdesk*.

The button additionally requires a linked customer on the ticket, a configured AI provider, and — for every variant except *ask for missing details* — a knowledge base with a sufficiently similar entry. No new permission is introduced: the button follows *Send helpdesk reply*, the same permission that gates the reply form.

Unlike every other AI call in the plugin this one runs synchronously, because an agent is waiting for it. It therefore has its own timeout (default 20 seconds) that should stay well below the timeout of any reverse proxy in front of Redmine, its own output budget, and a throttle per user and per ticket.

*If your logs were retained, rotate the affected keys.* The fix prevents new entries; it cannot remove those already written.
