h3. Added

* *The original recipients of a customer mail, one click away in the reply form.* A customer mail is often addressed to more than one person — a colleague, a shared team address, an account manager in Cc — but the reply form only ever prefilled the customer in *To* and left *CC* empty. Putting the rest of the thread back on the answer meant opening the original mail and retyping the addresses, so in practice they were dropped: the reply reached one person while nobody else on the original thread heard it. Behind *To* and *CC* there is now an *original recipients* button, listing the addresses the mail that opened the ticket was sent to, each with a checkbox — ticking one adds it to the field, unticking takes it back out. *To* offers the original @To:@ and *CC* the original @Cc:@, so the customer's own addressing is preserved rather than guessed at. The helpdesk's own mailbox address and the customer itself are filtered out, an address that appeared in both headers is offered once, and the button is absent altogether when nothing is left to offer. *BCC* has no button: an inbound @Bcc@ is stripped by the sending server and was never available to begin with.

h3. Upgrade notes

No migration and no new setting. The recipients of every incoming mail have been recorded in the message log all along, so the button works on existing tickets as soon as the plugin directory is replaced — including tickets that arrived long before this release.

Two details worth knowing. The addresses are filtered against the mailbox that actually *received* the mail, read from the message itself rather than from the mailbox the reply happens to go out through; a ticket whose original mailbox has since been disabled therefore still has the helpdesk's own address filtered out instead of offered back as a recipient. And an address that the agent has already put in the field by hand is recognised even in its @"Name" <address>@ form, so ticking it in the list cannot add the same person twice.
